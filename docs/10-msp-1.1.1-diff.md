# MSP schema diff — muse 1.0.3 → 1.1.1

Re-exported in place with the 1.1.1 binary (`muse schema generate-ts --out
fixtures/msp/msp-ts`, `muse schema generate-json-schema --out fixtures/msp/msp`).
`git diff` on `fixtures/msp/msp-ts/msp.d.ts` (1892 → 1966 lines),
`fixtures/msp/msp/msp.schema.json` and `fixtures/msp/msp/manifest.json` is the
complete change; this doc groups it with one line per item on what it means for
this client.

Fingerprints (`fixtures/msp/msp/manifest.json`, corroborated by a free
`initialize` against `muse serve`, which reports `serverInfo.version 1.1.1`):

- old: `sha256:03312c213efd14277a0e0a102f70adeae497a469ca4edf7242f479953ed758b7`
- new: `sha256:c669a30c2ee17d63192b227865b424d1d78b5d6c04d9f1c9e9b77b9cf03e6a4f`

Totals: methods +2 / −0 / changed 0; notifications +1 / −0 / changed 0; `$defs`
types +6 / −0 / changed 8 (2 doc-only); error-table rows +1; enum variants +3
across 3 enums; fields +4 added / 1 re-spelled. Nothing removed anywhere — the
diff is purely additive plus doc comments. All six new types are small and are
typed in `crates/muse-client/src/schema.rs`; nothing is left "not yet typed".

## Methods (+2)

- `item/readOutput` (params `ItemReadOutputParams`, result `ItemReadOutputResult`):
  byte-ranged fetch of stored full output the view truncated — the `outputRef`
  fetch path SS3.9/SS4.5.5 always pointed at. Read-only, works on loaded and
  unloaded sessions, no lease. Client impact: the app can now offer "show full
  output" on truncated tool/userShell cards; `MuseClient::item_read_output`
  added, nothing calls it yet.
- `view/subscribe` (params `ViewSubscribeParams`, result `ViewSubscribeResult`):
  attach this connection's live view subscription at an explicit cursor, with
  `(after, head]` replayed as ordinary view notifications before live events —
  the gap-free re-attach after `view/unsubscribe` (and after a `session/resume`
  on a still-loaded session that a prior unsubscribe detached, per the new
  `SessionResumeResult.viewCursor` doc). Client impact: the documented repair
  path for the unsubscribe-detached state; `MuseClient::view_subscribe` added,
  nothing calls it yet.

## Notifications (+1)

- `session/modelRouteUnserved` (params `SessionModelRouteUnservedParams`): an
  accepted `login.credential_update` installed a provider that cannot serve the
  session's standing model route. Disclosure only — the standing selection is
  unchanged (no `session/modelChanged` fires) and the repair is a routable
  `session/setModel`. Client impact: none today — `MuseFold` ignores unknown
  notification methods (`_ => Vec::new()`), so this renders as nothing; a future
  slice could surface it as a model card warning. Added to
  `MSP_NOTIFICATIONS`; no fold arm added deliberately.

## Types (+6 new, 8 changed)

New (all typed in `schema.rs`):

- `ItemReadOutputEncoding` (closed: `utf8` | `base64`) — text media is always
  `utf8`, binary `base64`; a third value would change the decode contract, so it
  stays closed like the other decode-contract enums.
- `ItemReadOutputParams` (`itemId`, `outputRef`, `sessionId`, optional
  `offsetBytes`/`lengthBytes`, default/max 6 MiB) — small read query shape.
- `ItemReadOutputResult` (`byteLen`, `content`, `encoding`, `eof`, `mediaType`,
  `offsetBytes`) — one stored-byte page; next page starts at
  `offsetBytes + byteLen`.
- `ViewSubscribeParams` (`sessionId`, optional `after`) / `ViewSubscribeResult`
  (`viewCursor`) — the subscribe-at-cursor pair.
- `SessionModelRouteUnservedParams` (`commandId`, `installedProviderId`,
  `modelId`, optional `providerId`, `sessionId`, `sourceRange`, `viewCursor`) —
  same cursor/sourceRange framing as the other session view events.

Changed:

- `ClientCapabilities` + `userInputDialogs?: boolean` — declares the client can
  render a `userInput/request` dialog; **absent means capable**, so this client
  (which predates the member) keeps today's contract without changing its
  handshake. `false` would make the host withhold `userInput/request`.
- `ErrorData` + `availability?: string` (the durable `ToolOutputAvailability`
  value on `outputUnavailable`), + `itemId?: string` and + `outputRef?: string`
  (the requested item/output on the `item/readOutput` error arms) — all plain
  additive-optional members; error rendering needs no change.
- `Item.turnId`: `turnId?: string` → `turnId?: string | null` — the schema now
  spells what the captures always showed (explicit `null` on `userShell`). The
  Rust mirror keeps `Option<String>` serializing as `null`, unchanged.
- `SessionConfig`: doc comment only (unknown keys are *ignored*, D-052; no
  surface change) — the empty `SessionConfig` mirror is unchanged.
- `SessionResumeResult.viewCursor`: doc comment only (resume on a still-loaded
  session that `view/unsubscribe` detached never re-attaches; re-attach with
  `view/subscribe`) — the struct is unchanged.
- `ReasoningEffort` (closed) + `max` between `xhigh` and `ultra` — **this
  retires transport-doc §4 item 6**: sending `max` is no longer `invalidParams`.
  `ReasoningEffort::Max` added; the closed-enum test now accepts it. The app's
  effort picker still does not offer `max`: its tiers are the library's
  `aui_protocol::ReasoningEffort`, which has no `max` yet — offering it is
  library work (agentic-ui), out of scope here.
- `TurnErrorKind` (open) + `authRequired` — a turn can now fail for auth; folds
  to the existing turn-failed rendering, no new UI needed.
- `ErrorKind` (open) + `outputUnavailable` (error-table row `-32041`,
  non-retryable) — the `item/readOutput` failure kind; error rendering branches
  on `kind` strings and tolerates it already.

Doc-only: the export header now says "STABLE surface only", and the
`SessionConfig` / `initialize` descriptions were reworded with no surface
change.

## What the client relies on — all unchanged

Framing, id spaces, `session/list` fields (`turnCount` et al.), approval and
userInput shapes, and every error `data.kind` the client branches on are
byte-identical. No `crates/muse-client` / `crates/muse-adapter` behaviour fix
was needed beyond absorbing the new surface. The known 1.1.1 behaviour change —
`muse serve` pruning turn-less sessions shortly after creation — is behavioural,
not schematic (nothing in this diff explains it); see `docs/CHANGELOG.md` and
the `docs/02-app.md` footer note.

Captures are real 1.0.3 wire recordings and keep replaying untouched: no type a
capture uses was removed or re-spelled, and `cargo test --workspace` (including
`schema_roundtrip` and every replay/parity snapshot) passes with no snapshot
regeneration.
