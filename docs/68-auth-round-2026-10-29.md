## 3. New `--steps` verbs

`provider-action:<provider>:<recheck|signin|signout>`, `signout-confirm`, `crumb:<n>`. `signin` and `signout`
**change a real CLI login**: run them only with throwaway `CLAUDE_CONFIG_DIR` / `CODEX_HOME` (recipe below).

## 4. Live-check recipe used (screen locked all session)

The binary was `target/debug/baaz` with `env -i HOME USER PATH=/usr/bin:/bin TMPDIR SHELL BAAZ_STATE_DIR=<tmp>/state
CLAUDE_CONFIG_DIR=<tmp>/claude CODEX_HOME=<tmp>/codex XDG_CONFIG_HOME=<tmp>/xdg`, plus `--no-connect --login
signed-in --steps … --screenshot`.
- A signed-in Codex throwaway: `printf sk-test | CODEX_HOME=<tmp>/codex codex login --with-api-key` reads "Connected ·
  API key", and `account/logout` removes it. Never sent a turn.
- To catch the busy frame: `BAAZ_CODEX=<wrapper>`, a script that runs `sleep 3` and then execs the real codex. A
  normal probe lands before the capture.
- Codex browser sign-in without opening the owner's browser: put a fake `open` first on `PATH` (it logs the URL), then
  poll `lsof -iTCP:1455 -sTCP:LISTEN`.

**Not seen live:** finishing a real browser sign-in for Claude or Codex (that needs the owner's hands and a real
account), the Back hover, and the account menu opened over a live window (it is a separate overlay window, so it only
appears in the probe's inline render). No click went through a real pointer: the screen was locked, so every press
was a `--steps` verb through the same handler a click reaches.
