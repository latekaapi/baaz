- **[app-core-2] Sidebar rendering is a second module hiding in app.rs** — `crates/harness/src/app.rs:2568` — medium — `render_nav_block`, `render_sidebar`, `rename_field`, `render_sidebar_empty`, `render_footer`, `render_rail` (`app.rs:2550-2873`) plus the sidebar-owned state (`sidebar_open`, `sidebar_width`, `renaming`, `rename`, `show_hidden`, `show_empty`, `show_archived`, `app.rs:410-468`) mix shell layout with session-list policy and never touch login, tier, or menus — Extract to `crates/harness/src/sidebar_view.rs` taking `&Harness` rows data and returning elements, leaving only the state fields behind.
- **[app-core-3] Dialogs, menus, palette, and toasts form a third module** — `crates/harness/src/app.rs:3426` — medium — `render_dialog`, `render_palette`, `render_toasts`, `render_overflow_menu`, `render_view_menu`, `render_account_menu`, `open_menu`, `move_menu`, `open_palette`, `confirm_palette`, `set_dialog`, `close_dialog`, `load_menu_sources` (`app.rs:1914-1946`, `2294-2502`, `2540-2549`, `2874-3039`, `3193-3201`, `3295-3533`, `3807-3851`) operate on the shared `Overlays` entity plus `Dialog`/`MenuKind`/`PaletteKind` selection state and are independent of login, tier, and session lifecycle — Extract to `crates/harness/src/dialogs.rs` (or move the render halves next to `overlays.rs`, which already owns the state per `docs/07-architecture.md` §2).
- **[app-core-4] Two parallel scripting mini-languages should live together** — `crates/harness/src/session.rs:1790` — medium — `Harness::step` (`app.rs:1547-1615`, shell verbs) and `SessionView::step` (`session.rs:1790-1964`, ~175 lines, ~30 verb arms from `"draft"` at `:1793` to `"wait"` at `:1955`) plus `run_login_steps`/`login_step` (`app.rs:1228-1299`) parse the same `--steps`/`--login-steps` surface in three places with no shared dispatch or verb registry — Extract all three into `crates/harness/src/steps.rs` behind one `verb → handler` table so `--steps` coverage (e.g. the missing sidebar-collapse verb noted in `docs/diagnosis/sidebar.md`) is visible in one file.
- **[app-core-5] Tier probe block is a separable concern in app.rs** — `crates/harness/src/app.rs:1362` — medium — `probe_tier`, `tier_banner`, `push_tier` (`app.rs:1362-1428`) with the `tier`/`tier_probing` fields (`app.rs:440-445`) implement the billing-guard probe lifecycle and only hand a `TierBanner` to the session view; nothing else in `Harness` reads the probe internals — Extract to `tier.rs` callers (or a `billing.rs` wrapper), leaving `Harness` with a single `tier: Option<Tier>` field.
- **[app-core-6] Sidebar drag/resize is a fourth extractable unit** — `crates/harness/src/app.rs:3726` — medium — Five fields (`sidebar_width`, `resizing`, `grab_x`, `start_w`, `drag_moved`, `last_release`, `app.rs:410-428`) exist only for `begin_resize`/`drag_resize`/`end_resize`/`persist_width`/`toggle_sidebar` (`app.rs:3714-3767`), which otherwise never interact with sessions, login, or menus — Extract to a `ResizeDrag` struct (new module or `layout.rs` beside the existing `layout::drag_width` used at `app.rs:3740`) holding the five fields and the four fns.
- **[app-core-7] SessionView is a god object: 152 methods across six concerns** — `crates/harness/src/session.rs:217` — medium — One struct (`session.rs:217-379`) owns the fold/client, the transcript render cache, the composer plus `@`/`/`/model/effort/mode menus, approvals/questions/feedback state machines, fork/retry/shell/clocks, and all render fns, with 152 methods in two `impl` blocks; the file's own section comments (`session.rs:14`, `session.rs:3208`) already mark the seams — Split along the existing seams: composer+menus (`1375-1790`, `2846-3228`), approvals/questions/shell/fork/retry (`3229-3736`), clocks (`3761-3888`), render (`2018-2846`), keeping `SessionView` as the thin state holder.
- **[app-core-8] Harness is a god object: 109 methods across login, sessions, search, and shell** — `crates/harness/src/app.rs:391` — medium — `Harness` (`app.rs:391-484`) plus 109 methods spanning connection/auth, login flow, tier, index/sessions/rename/hide/archive/undo, search palette, sidebar, menus/dialogs, and resize; after findings 1–6 are extracted the remainder is session-list ownership plus `render` assembly — Do findings 1–6 first, then reassess; whatever remains (session list + `render`) is the true `Harness`.
- **[app-core-9] Harness::render is 166 lines of assembly plus side effects** — `crates/harness/src/app.rs:3535` — medium — `render` (`app.rs:3535-3700`) sets the window title, settles an in-flight resize (`app.rs:3546-3550`), branches login-vs-shell, builds sidebar+centre+shell, and registers the `ShowAbout`/`ShowDocs`/`ToggleRightPane` actions (`app.rs:3659-3669`); title sync and resize settle are lifecycle, not rendering — Hoist the title/resize-settle writes into an `on_frame` pre-pass (or `after_render`-style hook) so `render` only composes elements.
- **[app-core-10] render_centre mutates session-swap state inside render** — `crates/harness/src/app.rs:3087` — medium — `render_centre` takes `&mut self`, calls `open_replay` and the C2 deferred-swap `swap_pending_in` (`app.rs:3088-3093`), consumes `focus_composer` via `mem::take` (`app.rs:3097`), and registers ~13 key-action listeners per frame; the swap is flag-guarded so it is correct, but render now owns lifecycle timing — Move the `pending_ready` swap and `open_replay` kick into the same pre-pass as finding 9, leaving `render_centre` (and its listeners) pure composition.
- **[app-core-11] render_transcript is 208 lines with two sources of truth** — `crates/harness/src/session.rs:2061` — medium — `render_transcript` (`session.rs:2061-2268`) refreshes `cached_turns`/`cached_full_output` when `live_len != cached len || follow` (`session.rs:2086-2087`), early-returns the empty state, builds the virtualised list, and records frame stats (`session.rs:2261`), while event handlers elsewhere read the live fold directly — Split into `refresh_render_cache` (already at `session.rs:2287`) as the single sync point, a `transcript_list` builder, and an `empty_or_loading` branch, and document that render reads only the cache.
