# Audit — Area 1: client-adapter (`muse-client`, `muse-adapter`)

Scope: `crates/muse-client` (`client.rs`, `frame.rs`, `schema.rs`, tests) and
`crates/muse-adapter` (`fold.rs`, `failure.rs`, `side.rs`, tests,
`harness-probe` bin). Read-only audit; no source changed. Builds on (not
re-derived): `turn_cancel`/`view_subscribe`/`view_unsubscribe` having no
caller, `reconnect_after_login` kept under `allow(dead_code)` per D25, echo
being billed, and the replay/perf baselines.

- **[client-adapter-1] `reindex` never remaps cached `Slot.turn` after `TurnRemoved` shifts indices** — `crates/muse-adapter/src/fold.rs:1633` — severity high — `remove_turn` (fold.rs:1622) applies `Delta::TurnRemoved`, which does `session.turns.remove(index)` (aui-protocol `delta.rs:162`), shifting every later turn down, but `reindex` remaps only `assistant_turns` and merely retains `items`/`approvals`/`inputs`/`todo`/`goal` slots whose stale `turn` index still looks live, so the next update to a later turn's block writes to the wrong turn (non-tool blocks update blindly at fold.rs:985). — Fix: in `reindex`, remap every cached slot's `turn` through the rebuilt `positions` map (drop slots whose turn id is gone) instead of retaining by raw index.
- **[client-adapter-2] `ServerRequest` bypasses gap buffering during `view/gap` backfill** — `crates/muse-client/src/client.rs:264` — severity high — `dispatch` parks only `MuseEvent::Notification` with a `session_id` and sends `ServerRequest` straight through, so an `approval/request` arriving mid-backfill folds immediately while its gated item's events are still parked, landing the approval card before/instead of alongside its tool card. — Fix: park `ServerRequest` events that carry a `sessionId` in `params` the same way notifications are parked, releasing them with the same cursor-dedup pass.
- **[client-adapter-3] Fold swallows every malformed payload silently** — `crates/muse-adapter/src/fold.rs:419` — severity medium — all decode failures (`session_started` fold.rs:427, `approval_mode_changed` fold.rs:461, `item` fold.rs:725, `approval_requested` fold.rs:1243, `user_input_requested` fold.rs:1383, `user_input_settled` fold.rs:1408, `approval_resolved` fold.rs:1296, plus the `_ => Vec::new()` catch-all) return empty deltas with no counter, log, or marker, so a server shape-change is invisible in the transcript. — Fix: count decode failures per session in `SideState` (or emit a `MarkerKind`-style diagnostic delta) and surface the count in the existing fixture tests.
- **[client-adapter-4] Synthesized `client/protocolError` never reaches the UI** — `crates/muse-client/src/client.rs:670` — severity medium — `read_loop` converts unparseable lines (and `null`-id errors at client.rs:705) into `client/protocolError` notifications, but the fold's catch-all (fold.rs:419) drops them to `Vec::new()` and nothing in `crates/harness` matches that method (only `client.rs` references it), so wire faults vanish. — Fix: fold `client/protocolError` into an error banner delta (or at minimum a marker turn) and handle it in `SessionView::apply` like other error paths.
- **[client-adapter-5] Responses arriving after the 180 s timeout are silently dropped** — `crates/muse-client/src/client.rs:249` — severity medium — `request_value` removes the pending entry on timeout, so when the late answer lands `handle_frame` (client.rs:694) finds no waiter and discards it without a trace, leaving no way to distinguish "server never answered" from "server answered late". — Fix: log (or emit a `client/protocolError`-style event for) responses with no matching waiter, including method-unknown responses.
- **[client-adapter-6] Per-session maps grow without bound** — `crates/muse-adapter/src/side.rs:98` — severity medium — `command_text` (one entry per command, via `remember_command` from `user_message` fold.rs:758 and `record_queued` fold.rs:240), `usage` (fold.rs:504), `seen_requests` (fold.rs:1247,1387) and `item_reasons` (fold.rs:1361) are never evicted (no `*.remove` exists for any of them), so a long-lived session's fold grows linearly with turn count; `record_queued` also stores the prompt text twice (`command_text` plus `QueuedTurn.text`). — Fix: prune `usage`/`seen_requests`/`item_reasons`/`command_text` entries when their turn is removed or completes, and store the queued text once (look it up from `command_text`).
- **[client-adapter-7] Gap-fill runs on an unjoined thread with silent abort and unbounded buffering** — `crates/muse-client/src/client.rs:751` — severity medium — each `view/gap` spawns a detached `muse-gapfill` thread (deduped only while one is active, fold.rs-adjacent gap.rs logic at client.rs:742-747) that `break`s silently on any `view/page` error/timeout (client.rs:763), blocks up to `REQUEST_TIMEOUT` (180 s) per page in an unbounded page loop, and parks live events in a `Vec` with no size cap while it runs. — Fix: bound the page loop and buffer, join/track the thread handle, and emit a visible event when backfill aborts so the existing `view/gap` marker row is not a lie.
- **[client-adapter-8] An event does not touch only its turn; several paths are transcript-wide** — `crates/muse-adapter/src/fold.rs:1550` — severity medium — every out-of-order `push_block` runs `shift_slots`, which scans all of `items`/`approvals`/`inputs`/`todo`/`goal` (fold.rs:1556-1560); a stale slot triggers `relocate_call`, a full scan of every turn's every block (fold.rs:1005-1019); every `remove_turn` runs `reindex`, rebuilding the full position map (fold.rs:1634-1640); per-chunk `item_delta` allocates a `String` plus a `delta.clone()` per apply (fold.rs:1204,1233), and `item`/`session_started`/approval/model/context handlers clone the whole params `Value` before deserializing (fold.rs:427,461,486,491,497,546,725). — Fix: keep a per-turn slot index so `shift_slots`/`relocate_call`/`reindex` touch only the affected turn, and deserialize from `&Value` (or `from_str` on the raw line) instead of cloning params per event.
- **[client-adapter-9] Approval by/allowed→state mapping is implemented twice** — `crates/muse-adapter/src/fold.rs:299` — severity medium — `MuseFold::resolve_approval` (fold.rs:300-315) and `Folded::approval_resolved` (fold.rs:1323-1331) each map `(by, allowed)` to `ApprovalState` with subtly different arms (the former folds `resolution.decision` into the rule fallback, the latter uses amendment/reason/mode-name), so a policy fix in one path silently diverges from the other; same class of duplication: cursor/session extraction in `MuseEvent::from_frame` (client.rs:139-151) vs `handle_frame` (client.rs:720-723), and `todo_state` (fold.rs:1723, enum domain) vs `todo_entry_state` (fold.rs:1854, free-string domain). — Fix: extract one `fn approval_state(by, allowed, rule) -> ApprovalState`, one `fn event_cursor_session(&Value) -> (Option<String>, Option<String>)`, and document why the two todo mappings differ (or unify them).
- **[client-adapter-10] `harness-probe` docstring says echo is free, and the binary sends a billed turn with no guard** — `crates/muse-adapter/src/bin/harness-probe.rs:17` — severity medium — line 17 claims "The echo provider is free" (contradicting D19: echo is a route, not a discount) while `main` unconditionally runs `turn_start` (harness-probe.rs:72-80), so a reader trusting the comment spends a real turn. — Fix: replace the comment with the D19 wording plus the spend-rule pointer, and require an explicit env opt-in (e.g. `HARNESS_PROBE_LIVE=1`) before `turn_start`.
- **[client-adapter-11] `turn_retry_scheduled` formats a string it immediately discards** — `crates/muse-adapter/src/fold.rs:691` — severity medium — the `text` built at fold.rs:694-703 is thrown away by `let _ = text;` (fold.rs:704), i.e. dead code plus a wasted allocation on every retry event, suggesting an unfinished "retry row" feature. — Fix: delete the formatting (or land the retry-row feature deliberately with a snapshot test).
- **[client-adapter-12] Typed surfaces with no wire coverage: `view/subscribe`, `item/readOutput`, `session/modelRouteUnserved`** — `crates/muse-client/tests/schema_roundtrip.rs:63` — severity medium — the request/result/params dispatch tables have no arms for `view/subscribe` params+result or `item/readOutput` params+result, and no arm for the `session/modelRouteUnserved` notification; the test's `UNTYPED_METHODS` assertion means this passes only because no capture carries them (verified: no `view/subscribe` or `modelRouteUnserved` in `fixtures/msp/*.jsonl`; `item/readOutput` appears solely in `synthetic-readoutput.jsonl`, which the test skips), and the fold additionally has no `session/modelRouteUnserved` arm so it falls into `_ => Vec::new()` (fold.rs:419). — Fix: add dispatch arms plus a real (or explicitly synthetic, fold-level) test for each, and either fold `modelRouteUnserved` into side state or document why it is dropped.
- **[client-adapter-13] `failure.rs` test omits the `authRequired` kind** — `crates/muse-adapter/src/failure.rs:125` — severity low — `title` handles `TurnErrorKind::AuthRequired` (failure.rs:51) but `every_known_kind_has_a_sentence_of_a_title` lists the other eight kinds without it, so a regression on that arm is untested. — Fix: add `("authRequired", "Authentication required")` to the table.
- **[client-adapter-14] `events()` docstring misdescribes crossbeam semantics** — `crates/muse-client/src/client.rs:348` — severity low — "Clone the receiver to fan out; every event is delivered once" reads as broadcast, but `crossbeam_channel::Receiver::clone` load-balances (each event goes to exactly one clone); harmless today (single consumer in `crates/harness/src/conn.rs:47`) but an invitation to split the transcript. — Fix: reword to "clones compete; keep exactly one consumer (the pump in `conn.rs`)".
- **[client-adapter-15] `open_enum Unknown` drops the original string and cannot round-trip** — `crates/muse-client/src/schema.rs:71` — severity low — an unknown server value deserializes to `Unknown` (original discarded) and re-serializes as `"Unknown"`, so a future server value both misrenders (via `as_wire() -> None` fallbacks, e.g. `"unknown"` in `block_for` fold.rs:1192) and breaks the byte-exact round-trip the schema tests otherwise enforce; the existing test only asserts `as_wire() == None`, never serialization. — Fix: retain the raw string (e.g. `Unknown(String)`) or add a test pinning current serialize behavior with a comment that it is lossy by design.
- **[client-adapter-16] 3.7 k-line single-file schema mirror multiplies per-method touch points** — `crates/muse-client/src/schema.rs:1210` — severity low — `schema.rs` holds ~200 items / 868 `pub` lines in one file (`Item` alone carries ~59 `pub` fields at schema.rs:1210), and adding one wire method requires touching the type, `MSP_METHODS`/`MSP_NOTIFICATIONS` (schema.rs:3647,3687), the three dispatch tables in `schema_roundtrip.rs`, and a `MuseClient` wrapper — with section separators (schema.rs:127ff) as the only organization. — Fix: split `schema.rs` into modules by surface (`item.rs`, `session.rs`, `approval.rs`, `account.rs`, …) and generate the dispatch-table checklist from one inventory (or a test that asserts every `MSP_METHODS` entry has request+result arms and a client wrapper).
- **[client-adapter-17] `account_read`/`account_login_cancel`/`account_logout` hand-roll what `call()` does** — `crates/muse-client/src/client.rs:524` — severity low — three methods duplicate the `request_value` + `from_value` + `map_err(MuseError::Json)` sequence because they take no params struct, instead of a shared `call_no_params::<R>` helper next to `call` (client.rs:362). — Fix: add the helper and route all three through it.
- **[client-adapter-18] Cancelled-turn marker renders raw server free text** — `crates/muse-adapter/src/fold.rs:614` — severity low — `turn_completed` uses `params.reason` verbatim (defaulting to `"Turn cancelled"`) as the `TurnCancelled` marker text with no length cap or normalization, unlike failures which go through the `failure.rs` table. — Fix: pass cancellation reasons through a small mapping (like `reason_sentence`) with truncation, keeping the raw code for bug reports.

Counts: high 2, medium 10, low 6.
