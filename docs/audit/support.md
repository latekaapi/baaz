# Audit — Area 3: support modules

Read-only audit of `crates/harness/src` support modules (sidebar, overlays, search, index, history, sessions, files, images, skills, tier, auth, conn, main, shot, plan, full_output, attachments), plus legacy/scripting/fixtures questions. No source file changed.

- **[support-1] Dead `available`/`coming_in` pair on slash commands** — `crates/harness/src/overlays.rs:338` — medium — `Command::available` returns `true` for every command and `coming_in` returns `""`, so `session.rs:1562` renders a toast with an empty detail for a state that can never trigger — Delete both methods and the `available` branch at the call site, keeping `ALL`/`slash`/`description`.
- **[support-2] Sidebar regroups and rebuilds every row on each render** — `crates/harness/src/sidebar.rs:181` — medium — `grouping()` sorts entries and builds a fresh `SessionSummary` per row, and `render_sidebar` (`app.rs:2571`) calls it on every render, so frame cost scales with session count — Cache the `Grouping` and rebuild only when `sessions`, selection, or clock-minute change.
- **[support-3] `Local::now()` sampled per row inside grouping** — `crates/harness/src/sidebar.rs:186` — low — `bucket(entry.updated, Local::now())` re-reads the clock for every entry, so rows near a day boundary can bucket inconsistently within one frame — Hoist one `now` before the loop and pass it to `bucket` and `elapsed`.
- **[support-4] `record_files` does one SELECT per record** — `crates/harness/src/search.rs:129` — medium — Deduplication prepares a `SELECT … LIMIT 1` and runs it per record, so a turn that writes N files costs N round-trips — Use `INSERT OR IGNORE` with a uniqueness index on `(path, session_id)` and drop the probe query.
- **[support-5] Index schema drift degrades silently to wire-only labels** — `crates/harness/src/index.rs:83` — medium — `read_at` returns an empty map when the `sessions` table/columns change, with no log line, so a Muse index upgrade looks like lost titles — Log a one-line warning (table vs column vs locked) via `eprintln!` at the three early returns.
- **[support-6] History cap and dedup only cover the newest entry** — `crates/harness/src/history.rs:40` — low — `append` drops runs over 200 and skips repeats only against the newest prompt, so alternating A/B resends grow the file to the cap with duplicates — Keep the cap, and skip append when the text equals any of the last 3 entries (unverified against real usage; cheap either way).
- **[support-7] Batch hide re-writes the store and rejoins per row** — `crates/harness/src/app.rs:2032` — medium — `hide_batch` calls `set_override` per id, and each call rejoins all rows, writes `sessions.json`, and rebuilds the search index — Add a `set_overrides(&[id], edit)` that rejoins, writes, and reindexes once.
- **[support-8] `@` walk silently truncates past 5000 files** — `crates/harness/src/files.rs:15` — low — `walk` breaks at `CAP` with no signal, so in a monorepo the mention picker quietly misses files — Record `truncated: bool` alongside the walk result and show "showing first 5000" in the picker when set.
- **[support-9] Oversize-image error truncates megabytes** — `crates/harness/src/images.rs:96` — low — The message divides bytes by 1048576 with integer division, so a 10.9 MB image reports "10 MB" — Format with one decimal (`{:.1}`) like `attachments.rs` already does.
- **[support-10] `skills::list` has no timeout** — `crates/harness/src/skills.rs:69` — medium — `Command::output()` blocks until `muse skills list --json` exits, so a hung CLI stalls the background task holding the `/` menu sources — Spawn with a bounded wait (e.g. 10 s) and kill on expiry, returning empty like the other failure modes.
- **[support-11] Tier card parser is wording-locked with a silent fallback** — `crates/harness/src/tier.rs:452` — medium — `parse_card` matches literal "subscribed to the … plan" / "pay-as-you-go" strings, and any TUI rewording lands in `Unavailable`, which only warns — Pin the two known sentences in a test (already partly done) and surface "probe stale / card unrecognized" distinctly from "no tty".
- **[support-12] `stored_name_and_email` re-reads `auth.json` per identity** — `crates/harness/src/auth.rs:100` — medium — `Identity::from_account` calls it on every `account/changed`, doing file IO and JSON parse for two display strings — Cache the pair keyed by `auth.json` mtime, the same key `tier::cached` already uses.
- **[support-13] Bridge thread per connection is never joined** — `crates/harness/src/conn.rs:69` — low — `forward` spawns `muse-bridge` and relies on channel-drop to end it, which is correct but leaves no join handle for shutdown ordering — Keep the design; name the thread per-connection and assert in tests that it exits when the client drops.
- **[support-14] Stale `/logout` doc comment names the deleted child** — `crates/harness/src/overlays.rs:266` — low — The `Logout` variant comment says "`muse logout`" but sign-out is `account/logout` on the wire since D22 — Reword to "`account/logout`".
- **[support-15] `reconnect_after_login` kept dead behind `allow`** — `crates/harness/src/app.rs:1049` — medium — The D25 reconnect helper is `#[allow(dead_code)]` pending one billed live turn; until that check it is legacy surface — Delete it once the owner confirms D25, or reference this finding from the login follow-up brief.
- **[support-16] Screenshot statics assume a single window** — `crates/harness/src/shot.rs:19` — medium — `PENDING_APPROVAL` and `STEPS_RUNNING` are process-global `AtomicBool`s, so a second window would corrupt the capture wait — Move both flags onto `Harness` (or a capture token) and pass them into `capture_and_quit`.
- **[support-17] `plan::prefix` hits the environment on every send** — `crates/harness/src/plan.rs:42` — low — `std::env::var_os(PREAMBLE_ENV)` runs per prompt although the variable never changes mid-run — Read it once in `Args` and pass a bool into `prefix`.
- **[support-18] All-headings plan reply duplicates headings as items** — `crates/harness/src/plan.rs:64` — low — `steps` drops itemless headings then falls back to paragraphs when `items` is empty, so a headings-only reply renders each heading as a numbered step — In the fallback, prefer the retained section labels over raw paragraphs.
- **[support-19] Attachment extension allowlist refuses new text kinds** — `crates/harness/src/attachments.rs:51` — low — `.mdx`, `.ipynb`, `.pem`, and extensionless configs fall through to refused/UTF-8-guess branches although they are plain text — Add the missing text extensions and treat unknown-but-UTF-8-decoding small files as text with a chip note.
- **[support-20] Scripting-only surface is large and undocumented in one place** — `crates/harness/src/main.rs:135` — medium — `--send`, `--steps` verbs (`send:`, `steer:`, `shell:`, `choose:`, `setmodel:`, `context:`, `image:`, `sidebar-width`, …), `--login-steps`, `--tier`, `--login`, `--approval-mode`, and `--session latest` are reachable only from flags, yet only `main.rs` lists them — Mark each verb's help row with "(scripting only)" and note the billed ones (`send:`, `steer:`, `--send`) with a cost warning.
- **[support-21] Phase probe scripts still send turns; captures are the ground truth** — `fixtures/msp/probe.py:1` — medium — `fixtures/msp/{probe_*.py,run*.py,drive.py,tui*.py}` are phase-era live clients and several reach `turn/start` (spend rule), while `transcript-*.jsonl` + `synthetic-*.jsonl` are the replayable truth — Add a header comment to each script naming whether it sends a turn, and point new work at `--replay` captures; keep `make-stress-300.py` as the stress-capture generator.
- **[support-22] `scripts/bundle.sh` is the one script that still serves releases** — `scripts/bundle.sh:1` — low — It builds `--release`, assembles and ad-hoc signs `Harness.app`, costs nothing, and is unrelated to wire probing — Keep it; do not group it with the `fixtures/msp` probe scripts in cleanup passes.
