Harness — where things stand

2026-09-12 · plain-words status for the owner · 5 sections

1. Where things stand

The chat app is finished and signed in two ways now, after a fix that moved sign-in onto the server's own account channel. A full review and speed pass then landed across nine packages with every screen proved pixel-identical before and after. Three things are left that only you can do: approve the Meta sign-in once, merge the library branches, and set the API-key budget.

2. Done

Sign-in rework (2026-09-11). The old sign-in read the wrong output of the wrong program, so the card sat on “Starting sign-in…” forever. Now there is one screen with two ways in: Continue with Meta account (a code appears in the app, you approve it in the browser — the subscription lane) and Use an API key (paste a key into a masked field that is wiped on submit — the pay-as-you-go lane). The API-key way was tested end to end from a signed-out machine, including a real reply from the model (“OK”). The Meta way reached the browser step three times, but each code expired before anyone approved it, so that half still waits on you.

Review and speed pass (2026-09-12). A read-only audit found 85 issues (two serious: updates landing on the wrong turn after a removal, and requests sent during a history backfill), then nine packages fixed them in order: measure first, library before app, simple fixes before structural ones. What you gain: fewer bugs, smaller files (app.rs went from 4009 to 1402 lines), and faster drawing. Every package was proved against 47 byte-identical screen captures, so nothing visible changed.

4. How to check it yourself

cargo run -p harness -- --replay fixtures/msp/transcript-approve.jsonl --theme dark

Opens the app replaying a saved approval chat in the dark theme — no server, no cost — so you can see the finished product as it looked live.

cargo run -p harness -- --no-connect --login choose --screenshot /tmp/login.png

Boots the sign-in chooser offline and saves a screenshot to /tmp/login.png — open it to see the two sign-in ways.

./target/debug/harness --bench fixtures/msp/synthetic-stress-300.jsonl

Streams a 300-turn synthetic chat through the app and prints timing numbers (build first with cargo build -p harness) — expect element, fold and frame percentiles plus idle-frame and memory figures like the table above.
